Despliegue con Vercel y Heroku

Guía paso a paso para publicar el frontend React/Vite en Vercel y la API Node/Express en Heroku, conectando MongoDB Atlas y Cloudinary.

1. Nota sobre el coste

Heroku no ofrece actualmente un nivel gratuito permanente. Sus dynos requieren un plan de pago o crédito/promoción vigente. Este manual explica la configuración técnica de Heroku, pero confirma el precio actual antes de publicar.

Vercel tiene un nivel Hobby con restricciones de uso y condiciones propias. MongoDB Atlas M0 y Cloudinary Free también tienen límites. Para un proyecto estrictamente sin coste, conserva la alternativa GitHub Pages + un proveedor de backend con free tier vigente descrita en el otro manual técnico.

3. Preparar los proyectos

  1. Comprueba que el frontend y el backend estén en repositorios GitHub accesibles desde Vercel y Heroku.
  2. Verifica que el frontend tenga package-lock.json, vite.config.js y los workflows de CI.
  3. Verifica que el backend tenga package-lock.json, package.json y src/server.js.
  4. Ejecuta las comprobaciones locales antes de desplegar.
cd app-TiendaWeb-frontend
npm ci
npm run lint
npm run test:ci
npm run build

cd ../app-TiendaWeb-backend
npm ci
npm start
No subas archivos .env. Usa las variables de entorno de cada plataforma. Si una credencial real se compartió o quedó en un commit, rótala aunque el archivo esté ignorado actualmente.

4. Base de datos y Cloudinary

MongoDB Atlas

  1. Crea un proyecto y un clúster M0 en MongoDB Atlas.
  2. Crea un usuario de base de datos con contraseña única.
  3. Agrega la red de salida del backend. Si el proveedor usa IPs dinámicas, Atlas puede requerir 0.0.0.0/0; usa una contraseña fuerte y el menor privilegio posible.
  4. Copia la cadena de conexión y reemplaza usuario, contraseña y nombre de base.
mongodb+srv://USUARIO:CONTRASENA@CLUSTER.mongodb.net/tiendaweb?retryWrites=true&w=majority

Cloudinary

Crea la cuenta y copia CLOUDINARY_URL desde el Dashboard. Esta variable va solo en Heroku. No debe aparecer en VITE_* ni en el repositorio.

5. Desplegar el backend en Heroku

Opción A: desde el Dashboard

  1. Crea una aplicación en el Dashboard de Heroku y elige una región.
  2. En Deploy, conecta GitHub y selecciona el repositorio del backend.
  3. Selecciona la rama main. Activa deploy automático solo después de probar el primer despliegue manual.
  4. En Settings > Config Vars, agrega las variables del bloque siguiente.
  5. En Deploy, pulsa Deploy Branch.
  6. Revisa los logs y copia la URL pública de Heroku.

Variables de Heroku

MONGO_URI=mongodb+srv://USUARIO:CONTRASENA@CLUSTER.mongodb.net/tiendaweb?retryWrites=true&w=majority
CLOUDINARY_URL=cloudinary://API_KEY:API_SECRET@CLOUD_NAME
AUTH_JWT_SECRET=SECRETO_ALEATORIO_DE_AL_MENOS_32_CARACTERES
ADMIN_EMAIL=admin@tu-dominio.com
ADMIN_PASSWORD_HASH=HASH_BCRYPT_DE_LA_CONTRASENA
FRONTEND_ORIGINS=https://TU-PROYECTO.vercel.app

No fijes manualmente PORT en Heroku: la plataforma proporciona ese valor. El backend del proyecto ejecuta npm start, que Heroku detecta desde package.json.

Opción B: Heroku CLI

Instala la CLI, inicia sesión y ejecuta los comandos desde la raíz del backend:

heroku login
cd app-TiendaWeb-backend
heroku create tiendaweb-api
heroku config:set MONGO_URI="mongodb+srv://..."
heroku config:set CLOUDINARY_URL="cloudinary://..."
heroku config:set AUTH_JWT_SECRET="SECRETO_LARGO"
heroku config:set ADMIN_EMAIL="admin@tu-dominio.com"
heroku config:set ADMIN_PASSWORD_HASH="HASH_BCRYPT"
heroku config:set FRONTEND_ORIGINS="https://TU-PROYECTO.vercel.app"
git push heroku main
heroku logs --tail --app tiendaweb-api

Si el repositorio contiene frontend y backend juntos, configura el directorio de trabajo/deploy correspondiente o despliega desde una copia donde el backend sea la raíz. Heroku debe encontrar el package.json del backend.

6. Generar secretos y credenciales

node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
node -e "require('bcryptjs').hash(process.argv[1], 12).then(console.log)" "CAMBIA_ESTA_CONTRASENA"

Usa el primer resultado como AUTH_JWT_SECRET y el segundo como ADMIN_PASSWORD_HASH. Conserva la contraseña original en un gestor de contraseñas, no en un archivo del proyecto.

7. Verificar el backend de Heroku

curl -i https://TU-APP.herokuapp.com/
curl -i https://TU-APP.herokuapp.com/api/articulos
curl -i -X OPTIONS https://TU-APP.herokuapp.com/api/articulos

La ruta raíz debe devolver JSON con el mensaje de API activa. Si aparece un error de conexión a MongoDB, revisa MONGO_URI y Network Access en Atlas.

Para crear los empleados iniciales, ejecuta el seed en un entorno que tenga las mismas variables y conexión:

heroku run npm run seed:empleados --app TU-APP
Ejecuta el seed una sola vez y entrega las credenciales iniciales por un canal seguro. No las pongas en issues, commits ni chats públicos.

8. Desplegar el frontend en Vercel

  1. En Vercel selecciona Add New > Project y conecta GitHub.
  2. Importa el repositorio de app-TiendaWeb-frontend.
  3. Si el repositorio contiene solo el frontend, deja la raíz del proyecto vacía. Si es monorepo, selecciona la carpeta del frontend.
  4. Vercel debería detectar Vite. Confirma npm run build como build command y dist como output directory.
  5. En Environment Variables, agrega VITE_API_URL con la URL HTTPS de Heroku, sin barra final.
  6. Selecciona los entornos Production y Preview según necesites y pulsa Deploy.
  7. Conserva la URL de producción, por ejemplo https://tiendaweb.vercel.app.
VITE_API_URL=https://TU-APP.herokuapp.com

La configuración actual de Vite usa base / fuera de GitHub Actions, que es la configuración adecuada para Vercel. No uses la base de GitHub Pages en este despliegue.

9. Configurar CORS entre Vercel y Heroku

Vuelve a Heroku y actualiza FRONTEND_ORIGINS con el origen exacto de producción:

FRONTEND_ORIGINS=https://TU-PROYECTO.vercel.app

El origen no incluye una ruta ni una barra final. Si necesitas probar previews de Vercel, agrega sus orígenes concretos separados por comas, por ejemplo:

FRONTEND_ORIGINS=https://TU-PROYECTO.vercel.app,https://rama-git-TU-PROYECTO.vercel.app

No pongas * como solución permanente. Después de guardar la variable, reinicia/redepliega Heroku.

10. CI/CD recomendado

El frontend ya incluye workflows para validar pull requests y desplegar GitHub Pages. Al usar Vercel, puedes elegir una de estas estrategias:

EstrategiaVentajaConfiguración
Vercel Git IntegrationPreviews automáticos y deploy sencillo.Importa el repo y configura VITE_API_URL en Vercel.
GitHub ActionsControles explícitos antes del deploy.Conserva CI y configura el deploy de Vercel con un token/secreto, nunca en texto plano.
Heroku Automatic DeploysEl backend se redepliega al actualizar main.Actívalo después de probar manualmente y protege la rama.

Una política recomendable es exigir que Validate frontend pase antes de aceptar pull requests y desplegar el backend desde main protegido.

11. Prueba completa de aceptación

  1. Abre la URL de Vercel en una ventana privada.
  2. Confirma que el login carga sin errores de red.
  3. Inicia sesión con el administrador y comprueba Artículos, Inventario, Pedidos y Ventas.
  4. Comprueba que el catálogo procede de la API de Heroku.
  5. Sube una imagen pequeña y confirma que la URL pertenece a Cloudinary.
  6. Registra una venta de prueba y comprueba su pedido.
  7. Prueba una cuenta de encargado y una de vendedor para validar permisos.
  8. Revisa la consola del navegador y los logs de Heroku: no debe haber errores CORS, 401, 404 o mixed content.
  9. Verifica en Vercel que el deployment de producción termina correctamente.
curl -i https://TU-APP.herokuapp.com/
curl -i https://TU-APP.herokuapp.com/api/articulos

13. Seguridad y mantenimiento

  • Rota toda credencial expuesta, incluso si fue retirada después del commit.
  • No coloques CLOUDINARY_URL, JWT, hashes ni MONGO_URI en el frontend.
  • Recuerda que cualquier variable VITE_* es visible en el navegador.
  • Limita CORS al dominio de Vercel y a previews necesarias.
  • Activa protección de rama en GitHub.
  • Revisa límites y facturación de Vercel, Heroku, Atlas y Cloudinary.
  • Haz respaldos de MongoDB antes de cambios destructivos.

14. Checklist final

  • MongoDB Atlas responde desde Heroku.
  • Cloudinary está configurado en Heroku.
  • Heroku ejecuta npm start y su ruta raíz responde.
  • FRONTEND_ORIGINS contiene el origen Vercel.
  • Vercel usa npm run build, dist y VITE_API_URL.
  • Login y rutas protegidas funcionan desde producción.
  • La carga de imágenes funciona.
  • La suite local de lint, tests y build pasa.
  • Los logs de Vercel y Heroku están limpios.
  • El plan y los límites de Heroku están confirmados.
